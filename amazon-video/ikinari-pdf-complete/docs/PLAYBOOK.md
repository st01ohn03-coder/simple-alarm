# 同じ品質を、別のアカウントで出すために

このプロジェクトを他の人・他の商品に渡したとき、品質が落ちる原因は3つしかない。

1. **環境が違う**（動かない・見た目が変わる）
2. **判断ができない**（何を訴求すべきか決められない）
3. **劣化に気づけない**（出来上がったものが良いか悪いか分からない）

それぞれに対して、何を用意してあるかを並べる。

---

## 1. 環境が違う ― 動かない・見た目が変わる

| 課題 | 対策 | 該当 |
|---|---|---|
| 必要なものが入っているか分からない | 実行前に全部調べて、足りないものの直し方まで出す | `node tools/doctor.js` |
| ffmpeg があっても H.264 で書き出せない | libx264・AAC・ebur128 などの有無まで個別に確認する | doctor |
| Chromium の場所が環境で違う | 環境変数 → 既知の場所 → Playwright 同梱の順に探す | `tools/config.js` |
| フォントが無くて豆腐になる | 使う文字だけを woff2 に同梱。ネットが無くても描ける | `src/fonts/` |
| OS のフォント差で行が変わる | 外部フォントに依存しない。文字送りも指定済み | `subset-fonts.js` |
| 画面サイズで崩れる | 1rem をキャンバス基準にして、縦横比で係数を変える | `timeline.js` の `fit()` |

**渡された人が最初にやること**

```bash
npm install
node tools/doctor.js
```

必須が1つでも欠けると終了コードが 0 にならないので、CI に置いてもそのまま使える。

---

## 2. 判断ができない ― 何を訴求すべきか決められない

動画の品質は、工程②（構成と原稿を決める）でほぼ決まる。
ここは自動化できないので、**判断の型**を渡す。

| 課題 | 対策 | 該当 |
|---|---|---|
| 商品ページを読む手間 | A+本文・比較表・箇条書き・星の分布・画像を一括取得 | `tools/fetch-product.js` |
| 何を考えればいいか分からない | 問いが並んだ下書きを自動生成する（取得した事実が埋まった状態で） | `BRIEF.md`（`new-project.js` が作る） |
| 判断の基準が属人的 | 購買障壁の絞り方・評価が割れている商品の扱いを文章にした | `WORKFLOW.md` の② |
| 前例が無い | 実例が根拠つきで残っている | `ANALYSIS.md` |
| 尺に収まるか書いてみないと分からない | 原稿を実測してシーンごとに合否を出す | `narration.py --check` |

**BRIEF.md が埋まっていれば、書く人が代わっても同じ構成になる。**
埋まっていない状態で `src/video.html` を触り始めると品質が落ちる。

---

## 3. 劣化に気づけない ― 良いか悪いか分からない

目視だけだと、作った本人以外には判断がつかない。機械が見られるものは全部機械に見せる。

| 見るもの | 落ちる典型例 | 基準 |
|---|---|---|
| 入稿ルールの表記 | 価格を書いてしまう、URL を入れてしまう | `compliance.profile` |
| レイアウト | 文言を足して画面からはみ出す | `qa.overflowPx` |
| 文字の大きさ | 小さい画面で読めない | `qa.minFontPctH` |
| コントラスト | 背景に文字が沈む | `qa.minContrast` |
| 動画仕様 | 解像度・コーデック・fps・音声トラック | `qa.minHeight` ほか |
| 音量 | 他の動画より極端に大きい／小さい | `qa.lufs` |
| 尺のずれ | 映像だけ作り直して音声が古い | `qa.avSkewSec` |

```bash
node tools/qa.js              # 34項目以上
node tools/qa.js --skip-video # 書き出し前でも、レイアウトと可読性は見られる
```

### コントラストの測り方

背景がグラデーションや製品画面なので、CSS からは背景色が分からない。
そこで**文字だけ透明にした画を撮り**、その領域の明るさを背景とみなして
文字色との比を出している。

この方法にしたのは、描かれた画素を明暗で二分する素朴なやり方だと、
細い文字のときに両側が同じ値に寄って 1.0:1 のような誤判定を出したため。

大きな文字は小さな文字より低いコントラストでも読めるので、
`qa.largeTextPx` 以上は `qa.minContrastLarge` を使う。

### この検品が実際に見つけたもの

導入したときに、目視では通っていた次の欠陥が出た。すべて直してある。

| 箇所 | 実測 | 原因 |
|---|---|---|
| 「ページ編集」タグ | 2.2:1 | 白文字を橙(#F49807)に乗せていた |
| 「Ver.13」 | 2.1:1 | 明るい青の上に水色 |
| サブスクの棒ラベル | 3.1:1 | 白文字をグレーに乗せていた |
| 1:1 版の本文 | 高さの1.3% | 幅基準で文字サイズを決めていた |

## 4. 設定を1か所に集める

配色・尺・声・検品の基準は全部 `project.json` にある。
ツールはここを読むので、**書き換える場所を探す必要がない。**

```
project.json
├── product      ASIN・商品名・slug（書き出しファイル名になる）
├── theme        配色とフォント → src/theme.css に反映
├── video        fps・画質・プリセット・納品するもの
├── narration    声・速度・音量・環境音
├── qa           検品の基準値
└── compliance   使うルールと、根拠を示した主張
```

矛盾した設定は読み込み時に止まる。たとえば `narration.targetLufs` が
`qa.lufs` の範囲外だと、書き出す前にエラーになる。

```bash
node tools/apply-config.js   # theme.css に反映
```

## 5. 別の商品で始める

```bash
node tools/new-project.js B0XXXXXXXX --dir ../my-product
cd ../my-product
npm install && node tools/doctor.js
```

エンジン一式と図版とドキュメントが複製され、`project.json` の ASIN と slug が
差し替わり、商品ページから素材が集まり、`BRIEF.md` が事実入りで生成される。

**引き継がないもの**（前の商品の情報が混ざると事故になるため）

- `src/assets/` の画像
- `dist/` の書き出し
- `compliance.allowedClaims`（根拠のある主張は商品ごとに違う）

`src/video.html` と `tools/narration.py` の原稿は前の商品のまま入る。
これは形の見本で、`BRIEF.md` を埋めながら書き換える前提。

## 6. CI に置く

`.github/workflows/video-qa.yml` が、`amazon-video/` を触った変更で走る。

- 環境の確認
- 表記の点検と、ルール自体の自己診断
- `project.json` と生成物がずれていないか
- レイアウトと可読性の検品
- `dist/` に mp4 があれば動画の検品も

mp4 をリポジトリに入れていなくても、レイアウト・可読性・表記までは毎回見られる。

- [ ] `node tools/lint-copy.js --selftest` が通る

- [ ] 素材の権利を確認した
- [ ] `BRIEF.md` が埋まっている（次に触る人が判断をたどれる）
