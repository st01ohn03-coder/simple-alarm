AMAZON PRODUCT VIDEO — WORKFLOW

Amazon 商品動画 制作フロー

ASIN を渡してから納品までの6工程。青はコマンドで自動化済み、金は人が判断する工程、赤は通らないと先に進めない検品。 1商品あたり、判断工程を除けば実行時間は5分ほど。

自動（コマンド1本）
人が判断する
検品ゲート
1調査

商品ページから素材と情報を集める

タイトル・箇条書き・A+（商品紹介）本文・比較表・星の分布・商品画像・A+画像を一括取得する。

成果物　build/<ASIN>/product.json ／ img/*.jpg（35枚前後）
tools/pipeline.sh fetch <ASIN>
▼
2設計

構成と原稿を決める

上位版と下位版の差、実績の根拠、レビューの傾向から、潰すべき購買障壁を決める。シーン構成・画面文字・ナレーション原稿・使う画像を確定させる。

触るもの　src/video.html ／ src/assets/ ／ tools/narration.py の LINES ／ src/timeline.js の SCENES
人（または Claude）が判断
python3 tools/narration.py --check
▼
3文字

フォントをサブセット化する

画面に出る文字だけを Noto Sans JP から切り出す。ここを飛ばすと、新しく足した漢字が豆腐になる。

成果物　src/fonts/*.woff2（4ウェイト・各60KB前後）
node tools/subset-fonts.js
▼
4音声

ナレーションを合成する

セリフごとに合成し、実測して −19 LUFS に揃えてから配置。環境音を20dB下に敷いて −16 LUFS で書き出す。シーン区間は timeline.js から読むので、尺を変えても自動で追従する。

成果物　dist/narration.m4a（39.4秒 / 約0.9MB）
python3 tools/narration.py
▼
5映像

動画を書き出す

ヘッドレス Chromium で1フレームずつ描いて、JPEG を ffmpeg に直接流す。中間ファイルを作らないのでフレーム落ちが起きない。16:9 と 1:1 を同じ実装から出す。

成果物　dist/*_16x9_1080p.mp4 ／ *_1x1_1080.mp4（各60秒・40秒で完了）
node tools/render.js --preset 16x9node tools/render.js --preset 1x1
▼
6検品

納品できる状態か機械で確かめる

全シーンのレイアウトが余白に収まっているか（16:9・1:1 とも）、JSエラーがないか、解像度・コーデック・fps・音声トラック、ラウドネスとトゥルーピーク、映像と音声の尺ずれ。34項目。

落ちたら　②へ戻る。1件でも外れると終了コードが 0 にならない
node tools/qa.js
⟲
検品で落ちた項目は、ほぼ②の設計に原因がある。文言を足してレイアウトがはみ出した、原稿が長くてシーンをはみ出した、のどちらか。②に戻って直し、③以降をやり直す。
自動化していない理由　②の構成と原稿は、商品ごとに「何が購買障壁か」を読み解く工程で、機械的な変換では決まらない。 ここだけは人（または Claude）が判断し、残りはすべてコマンドに寄せている。
価格は動画に入れない　Amazon の商品動画ガイドラインで価格・割引表記は認められていない。買い切りの訴求は支払い回数の比較に置き換える。詳しくは docs/ANALYSIS.md 第4章。
