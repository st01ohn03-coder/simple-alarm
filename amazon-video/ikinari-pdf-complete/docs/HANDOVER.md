## 3. 決まっていることと、その理由

引き継いだ人が「なぜこうなっているのか」で迷わないように、判断の経緯を残す。
分析の詳細は [`ANALYSIS.md`](ANALYSIS.md)、構成の詳細は [`SCRIPT.md`](SCRIPT.md)。

### 潰す購買障壁を4つに絞った

指名検索で来る人が多い商品なので、認知ではなく**買う直前の引っかかり**を外す方針にした。

| 障壁 | 根拠 | 打ち手 |
|---|---|---|
| 自分の用途に足りるか分からない | 機能が多く伝わりにくい | 実画面で基本機能4つ（S3） |
| 上位版を買う理由が分からない | 差が比較表の奥にある | 「COMPLETE だけの機能」を2回明示（S4・S5） |
| 買い切りは損しないか | A+ が買い切りを推している | 支払い回数を可視化（S7） |
| 買ってから違ったと思いたくない | ★3.3 で星1が21% | 対応環境を最後に明示（S8） |

### 価格を動画に入れていない

A+ には「5年で105,820円お得」という強い訴求があるが、**Amazon の商品動画ガイドラインで
価格・割引表記は認められていない。** 支払い回数の比較（毎年 vs 1回）に置き換えてある。

金額を出したくなったら、まず [`compliance/amazon-jp.json`](compliance/amazon-jp.json) の
`price` ルールを見ること。`node tools/lint-copy.js` が機械的に止める。

### 尺を39.4秒にした

ナレーションが収まる長さから各シーンを逆算した結果。
先に34.0秒で作ったが、原稿が入らなかった。

**シーンの長さは `src/timeline.js` の `SCENES` が唯一の正。**
`tools/narration.py` がそこを読むので、片方だけ古くなることはない。

### 配色を途中で変えた

可読性の検品を入れたところ、目視では通っていた4件が落ちた。全部直してある。

| 箇所 | 実測 | 対応 |
|---|---|---|
| 橙のタグ | 2.2:1 | 白文字をやめて濃い文字に |
| 「Ver.13」 | 2.1:1 | 明るい青用の文字色を追加 |
| 棒グラフのラベル | 3.1:1 | 背景のグレーを暗く |
| 1:1 版の本文 | 高さの1.3% | 縦横比で基準サイズを変えるように |

**元の色に戻すと検品で落ちる。** 変えるなら [`PLAYBOOK.md`](PLAYBOOK.md) のコントラストの項を先に読む。

### 実績数値に注記を付けている

「15年連続第1位」「360万本」「15,000社」は自社調べ。
景品表示法の観点から、調査主体・対象・期間を画面に出したまま使っている。

**注記を消して使い回さないこと。** 消すなら主張ごと消す。

## 4. 申し送り

### 先に片づけたほうがよいこと

1. **素材の権利を確認する。**
   `src/assets/` の画像は商品ページ掲載画像から切り出したもの。
   自社の商品ページなら問題ないが、公開前に確認が要る。

2. **添付画像が届いていない。**
   依頼時に「添付した画像で作って」という指示があったが、画像がセッションに届かなかった。
   そのため商品ページの画像で代替している。**意図された画像があるなら差し替える。**
   `src/assets/` に同じファイル名で置けば、コードの変更なしに反映される。

3. **評価が動いている。**
   分析時点は ★3.3（82件）。その後の取得で ★3.4（83件）になっていた。
   星1の割合を前提にした判断（S8 で仕様を明示する）をしているので、
   大きく動いていたら [`ANALYSIS.md`](ANALYSIS.md) の第2章を見直す。

### 知っておくとよいこと

4. **商品ページの取得は、回によって取れる量が違う。**
   A+ 本文が 10,898字 取れたこともあれば 2,840字 のこともあった。
   軽い版が返ってくることがあるため。少ないと感じたら時間をおいて取り直す。

5. **短時間に何度も取得するとボット検知に当たる。**
   「ショッピングを続ける」の中間ページが返る。
   `fetch-product.js` は Playwright で描画し直す代替経路を持っているので自動で復帰するが、
   それでも駄目なら数分おく。

6. **レビュー本文は取れない。** Amazon がログインを要求する。
   星の分布と件数までは商品ページから取れる。

7. **9:16（縦型）は未設計。**
   `project.json` の `presets` にはあるが `deliverables` から外してある。
   書き出しはできるが、レイアウトを縦型向けに作っていないので検品は通らない。
   縦型が必要になったら、正方形と同じ要領で `.scene.sq` 相当の調整が要る。

8. **`node_modules` をシンボリックリンクにするならコミットに注意。**
   `.gitignore` を直して両方無視するようにしたが、以前は末尾スラッシュ付きだけだった。

### まだ手を付けていないこと

9. **A/Bテスト案が未実施。** [`ANALYSIS.md`](ANALYSIS.md) の第5章に5案ある。
   フック違い・15秒版・上位版訴求の位置・声違い・レビュー変化の検証。

10. **CI が未検証。** `.github/workflows/video-qa.yml` は追加済みだが、
    GitHub 上でまだ走っていない。PR を作れば初回が走る。

## 5. 引き継いだ人が最初にやること

```bash
git clone <リポジトリ> && cd <リポジトリ>/amazon-video/ikinari-pdf-complete
npm install
npx playwright install chromium
pip install edge-tts

node tools/doctor.js      # 動く環境か確かめる（足りなければ直し方が出る）
node tools/qa.js          # いまの成果物が基準を満たしているか
```

**`doctor` と `qa` が両方通れば、引き継ぎは成功している。**
片方でも落ちたら、出力に直し方が書いてあるのでそこから。

そのあと、作り直せることを確かめておくと安心できる。

```bash
tools/pipeline.sh build   # 1分半ほど
tools/pipeline.sh qa
```

同じ動画が出れば、環境も手順も引き継げている。

## 6. 触るときの注意

| やりたいこと | 触るファイル | 忘れやすいこと |
|---|---|---|
| 文言を変える | `src/video.html` | 新しい漢字を足したらフォントの作り直しが要る（`build` に含まれる） |
| 尺を変える | `src/timeline.js` の `SCENES` | ナレーションを作り直す |
| ナレーションを変える | `tools/narration.py` の `LINES` | `--check` で尺を確かめる |
| 色を変える | `project.json` の `theme.colors` | `node tools/apply-config.js` |
| 画像を差し替える | `src/assets/*.jpg` | 同じファイル名なら変更不要 |
| 検品基準を変える | `project.json` の `qa` | 入稿先が変わったときだけ |

**何を変えても、最後に `tools/pipeline.sh qa` を通す。**
1件でも外れたら終了コードが 0 にならない。
