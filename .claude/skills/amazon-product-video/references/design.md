## レイアウトの決まりごと

### 大きさは画面幅を基準にする

`1rem = キャンバス幅の1%` に固定してある。16:9 と 1:1 が同じ実装から出せるのはこのため。

ただし正方形や縦型は幅が狭いぶん、幅だけで決めると**画面の高さに対して文字が小さくなりすぎる**。
縦長になるほど基準を上げてそろえている（`timeline.js` の `fit()`）。

| 縦横比 | 係数 |
|---|---|
| 1.5 以上（16:9 など） | 1.00 |
| 0.9〜1.5（1:1 など） | 1.25 |
| 0.9 未満（9:16 など） | 1.55 |

### 見出しの大きさは CSS 変数で指定する

```html
<h2 class="headline" style="--fs:4.9rem">…</h2>
```

インラインの `font-size` にすると、正方形版で縮めるときに上書きできない。
`.scene.sq h2.headline` が `--fs` に係数を掛けている。

### 16:9 は縦が足りない

`1920×1080` で余白を引くと、中身に使えるのは **840px ほど**しかない。
見出し＋本文＋大きな画像を縦に積むと確実に溢れる。
横に広いぶん、左右2カラム（`.splitwrap`）にすると収まることが多い。

### アニメーションは CSS ではなく JS で持つ

`render(t)` が時刻から全要素の `opacity` と `transform` を計算する純関数になっている。
CSS の transition / animation は一切使っていない。
1フレームずつ正確に seek してキャプチャするために必要で、これを崩すとフレームが飛ぶ。

## 可読性の基準

`project.json` の `qa` に入っている。入稿先が変わったらここを直す。

| 項目 | 既定 | 意味 |
|---|---|---|
| `minFontPctH` | 1.7 | 文字の高さ下限（キャンバス高さに対する%） |
| `minSmallFontPctH` | 1.05 | 注記だけに許す下限 |
| `minContrast` | 4.5 | 文字と背景のコントラスト比 |
| `minContrastLarge` | 3.0 | 大きな文字に許す比 |
| `largeTextPx` | 32 | 「大きな文字」の境目 |
| `overflowPx` | 40 | 余白からのはみ出し許容（拡大演出ぶん） |

### コントラストの測り方

背景がグラデーションや操作画面なので、CSS からは背景色が分からない。
そこで**文字だけ透明にした画を撮り**、その領域の明るさを背景とみなして文字色との比を出している。

描かれた画素を明暗で二分する素朴な方法も試したが、細い文字だと両側が同じ値に寄って
**1.0:1 のような誤判定**を出したので捨てた。文字なしの画で測るのが確実。

### 色を決めるときの注意

白文字を乗せると危ないのは、**橙・黄・明るい緑**。

| 背景 | 白文字のコントラスト | どうするか |
|---|---|---|
| 橙 `#F49807` | 2.2:1 | 白ではなく濃い文字（`--on-orange`）を乗せる |
| 緑 `#24A05C` | 3.4:1 | 暗くする（`#1E864D` で 4.6:1） |
| 紫 `#A96FA8` | 3.8:1 | 暗くする（`#986497` で 4.6:1） |
| 赤 `#E23C2E` | 4.3:1 | わずかに暗くする（`#D63528`） |
| 濃い青 `#0460B5` | 6.3:1 | そのままで良い |

明るい青の背景に水色の文字を置くのもよく落ちる（実測 2.1:1）。
明るい背景の上に置く文字は専用の色（`--on-blue`）にしてある。

## 検品が落ちたときの読み方

| 落ちた項目 | だいたいの原因 |
|---|---|
| 表記 | 価格や URL を書いてしまった。`node tools/lint-copy.js` に理由と直し方が出る |
| レイアウト（余白） | 文言を足してはみ出した。文字を減らすか `--fs` を下げる |
| レイアウト（画面外） | 同上だが深刻。拡大演出と重なっている可能性もある |
| 文字サイズ | 正方形版で落ちやすい。その要素だけ大きくするか、注記扱いにする |
| コントラスト | 明るい背景に淡い文字。`project.json` の色を直して `apply-config.js` |
| 整合（尺） | `timeline.js` を変えたあと書き出し直していない |
| 整合（映像と音声） | ナレーションを作り直していない。`python3 tools/narration.py` |
| ラウドネス | 音声を手で加工した。`tools/narration.py` から作り直す |

**ほとんどは②（構成と原稿）で文言を足した副作用。** ②に戻って直すのが早い。

## 映像まわりの落とし穴

### 背景が本文を隠す

`position:absolute` の要素は、**位置指定のない通常フローの要素より後に描画される**。
背景レイヤーに `z-index` を指定しないと、transform を持たないテキストが背景に隠れて消える。

見出しの文字は1文字ずつ transform を持っているので見えるのに、
補足テキストや小見出しだけが消える、という分かりにくい出方をする。

```css
.scene > *:not(.bg):not(.grid-lines):not(.stripe){ position:relative; z-index:2; }
```

### 1文字ずつ span にすると禁則処理が効かない

見出しを1文字ずつアニメーションさせるために `inline-block` の span に割ると、
ブラウザがどこでも改行できてしまい、**句読点が行頭に来る**。

行頭に来てはいけない文字は、直前の文字と同じ span にまとめている。
`<br>` をまたいだら区切り直す。`</span>。` のようにタグをまたぐケースもあるので、
直前の span はテキストノードをまたいで保持する。

### クラス名の衝突

棒グラフに付けた `.bar.sub` が、本文用の `.sub`（`margin-top:1.8rem`）を拾って
レイアウトが崩れたことがある。汎用的な名前を修飾子に使わない。

## 音まわりの落とし穴

### `amix` は入力が終わるたびに再正規化する

短いセリフを `adelay` で並べて `amix` でまとめると、セリフが終わるたびに
残りの入力の音量が上がる。**実測で最初と最後に 12.9 dB の差**が出た。

`normalize=0` は新しい ffmpeg にしかない。ミックスは ffmpeg ではなく
Python で足し合わせている（`tools/narration.py`）。

### `alimiter` は自動レベル調整が既定でオン

`level` が既定 true。有効だと全体にゆるやかなゲインランプがかかる。
`alimiter=limit=0.87:level=disabled` のように必ず切る。

### `apad` は無限に音を作り続ける

`apad,atrim=0:N` だと ffmpeg が終了しないことがある。尺は出力側の `-t` で切る。

### `execFileSync` は成功時 stdout しか返さない

ffmpeg は `-i` だけのときも `ebur128` の集計結果も **stderr** に書く。
測定結果を読みたいなら `spawnSync` で両方拾う。

### 動的な正規化は使わない

`loudnorm` に任せると区間ごとに音量が揺れる。
セリフごとに実測して静的ゲインで揃えている。実測でセリフ間の差は 1.1 dB。

## 音

| | |
|---|---|
| 音声合成 | edge-tts（Microsoft Edge のニューラル音声） |
| 声 | `ja-JP-NanamiNeural`（女性）／`ja-JP-KeitaNeural`（男性） |
| 速度 | `+6%` が既定 |
| セリフごと | 実測して -19 LUFS に揃える |
| 完成トラック | -16 LUFS、トゥルーピーク -1 dBFS 以下 |
| 環境音 | 自前合成のパッド。ナレーションの約 20 dB 下。`--no-music` で外せる |

原稿を書くときは、**TTS が読み違える語をカタカナで書く**。
PDF→ピーディーエフ、AI→エーアイ、Wi-Fi→ワイファイ。英数字の並びは特に危ない。

セリフはシーン開始の 0.45 秒後から読み始め、シーン終了の 0.30 秒前までに読み終える。
シーン区間は `src/timeline.js` が唯一の正で、`tools/narration.py` がそこから読む。
尺を変えたらナレーションを作り直すだけで追従する。

```bash
python3 tools/narration.py --check
```
