# 入稿できない表記と、その理由

`tools/lint-copy.js` が機械的に拾う。ルールの実体は
プロジェクト側の `docs/compliance/<profile>.json`。

```bash
node tools/lint-copy.js            # 点検
node tools/lint-copy.js --strict   # 「要確認」も失格にする
node tools/lint-copy.js --selftest # ルール自体が壊れていないか
```

---

## 止めるもの（error）

### 価格・割引

12,980円、￥12980、30%OFF、税込、定価 など。

商品動画に価格は入れられない。価格は変動するので動画の差し替えが必要になるし、
ガイドライン上も認められていない。

**買い切りを訴求したいとき**は、金額ではなく**支払い回数**の比較に置き換える。
「毎年払う」対「1回だけ」なら、金額を一切出さずに同じことが伝わる。

### 販促表現

セール、キャンペーン、期間限定、今だけ、クーポン、送料無料 など。
価格と同じ理由。必要なら商品ページ側の表記で行う。

### Amazon への言及・カートへの誘導

Amazon、カートに入れる、今すぐ購入、プライム会員 など。
動画内から購買動線に言及することはできない。

### URL・メールアドレス・電話番号

外部への誘導になる。動画からは外す。

### 競合の実名

比較広告になり、根拠の提示が必要になる。
「サブスクリプション型」のような一般名詞にとどめる。

実名を持っているなら `project.json` の `compliance.competitorNames` に入れておくと、
リンタが自動でルールに足して拾ってくれる。

---

## 確認を促すもの（warn）

### 根拠のない最上級

No.1、第1位、日本一、世界一、最高、唯一 など。

景品表示法の観点から、**調査主体・対象・期間を同じ画面に出す**必要がある。
注記は `src/timeline.js` の `NOTE` に書き、`NOTES` でどのシーンに出すかを決める。

根拠を示した主張は `project.json` の `compliance.allowedClaims` に入れておくと、
以降は警告されない。**商品ごとに違うので、別商品のプロジェクトに引き継がないこと。**

注記を消して使い回すのが一番危ない。消すなら主張ごと消す。

### 効能・効果

治る、治療、効能、症状が改善 など。商材によっては薬機法の対象になる。

### 返金・保証

全額返金、永久保証 など。条件を動画では書ききれず誤認を招きやすい。

---

## ガイドラインではないが守ること

**音を消しても意味が通るように作る。**

商品ページの動画はミュートで自動再生される。音に頼った構成にすると、
ほとんどの視聴者には何も伝わらない。伝えたいことは画面文字に出し、
ナレーションは補助に留める。

---

## ルールを直すとき

各ルールには「拾うべき例」と「拾ってはいけない例」が入っている。

```json
{
  "id": "price",
  "severity": "error",
  "why": "なぜ止めるのか",
  "fix": "どう直すか",
  "pattern": "正規表現",
  "examples": { "ng": ["12,980円"], "ok": ["支払い1回だけ"] }
}
```

正規表現を直したら `--selftest` で確かめる。
JSON の中で `\s` を書くときのエスケープを間違えて、ルールが丸ごと効かなくなったことがある。
自己診断はそれを見つけるために入れてある。

別のマーケットプレイスや媒体に出すなら、`docs/compliance/` に新しいファイルを作り、
`project.json` の `compliance.profile` でそれを指す。
