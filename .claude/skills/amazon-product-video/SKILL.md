# Amazon 商品動画をつくる

ASIN を渡されてから納品するまでを、**判断が要る工程**と**機械に任せる工程**に分けて進める。
機械に任せられるところは全部スクリプトにしてあるので、あなたの仕事はほぼ工程②に集中する。

## まず状況を見分ける

| 状況 | やること |
|---|---|
| 新しく作る | 「セットアップ」→「制作」の順に進む |
| すでにプロジェクトがある（`project.json` がある） | 「制作」の②から入る |
| 既存の動画を直したい | 該当ファイルを直し、必ず「⑥ 検品」まで通す |

## セットアップ

スキル同梱の雛形を作業場所に展開する。**雛形はそのままでも動く状態**なので、
まず一度通して書き出してみると、以降の変更の影響が分かりやすい。

```bash
bash <skill-dir>/scripts/new-video-project.sh <ASIN> <作る場所>
cd <作る場所>

npm install                            # playwright・ffmpeg・pngjs
npx playwright install chromium        # 未取得なら
pip install edge-tts                   # ナレーション用（無くても無音で書き出せる）

node tools/doctor.js
```

`doctor.js` は Node・Chromium・ffmpeg（libx264 と AAC の有無まで）・Python・edge-tts・
フォント・設定の妥当性を調べ、足りないものの直し方まで出す。
**必須が1つでも欠けていたら、先にそれを片づける。** 欠けたまま進めると、
書き出しの最後で失敗して原因が分かりにくくなる。

`new-video-project.sh` は雛形の展開に加えて、商品ページから素材と情報を集め、
判断用の `BRIEF.md` を事実入りで生成する。

## 制作

### ① 調査

```bash
node tools/fetch-product.js <ASIN>
```

`build/<ASIN>/` にタイトル・箇条書き・A+（商品紹介）本文・比較表・星の分布・画像が落ちる。
セットアップで済んでいれば飛ばしてよい。

**レビュー本文は取れない**（Amazon がログインを要求する）。
星の分布までは取れるので、評価が割れているかどうかは判断できる。

### ② 構成と原稿を決める ← ここがあなたの主戦場

動画の品質はここでほぼ決まる。機械的な変換では決まらないので自動化していない。

手順と判断の基準は [`references/workflow.md`](references/workflow.md) に書いてある。**読んでから始める。**
実例（何をどう判断したか）は [`references/example.md`](references/example.md) にある。

要点だけ先に言うと、

- **指名検索で来る商品は、認知ではなく「買う直前の引っかかり」を外すのが動画の仕事。**
  だから「この商品はすごい」ではなく「あなたの用途に足りる」「上位版を選ぶ理由はこれ」
  「買ってから違ったと思わない」を順に潰す構成にする。
- **A+（商品紹介）が一番の資産。** メーカーが自分で何を売りにしているかを書いているので、
  訴求の候補はだいたいそこに揃っている。比較表があれば上位版の差も取れる。
- **評価が割れている商品ほど、期待値をそろえる要素を最後に入れる。**
  星1が2割を超えるなら「思っていたものと違った」が主因のことが多く、
  対応環境や数量を隠さず出すのが CVR にもレビューにも効く。

`BRIEF.md` を埋めてから、次を書き換える。

| 変えるもの | ファイル |
|---|---|
| 画面に出る文言・構成要素 | `src/video.html` |
| シーンの長さ・出るタイミング | `src/timeline.js` の `SCENES` |
| 商品画像・操作画面 | `src/assets/*.jpg`（`build/<ASIN>/img/` から切り出す） |
| ナレーション原稿 | `tools/narration.py` の `LINES` |
| 配色・声・検品基準 | `project.json` |

書きながら2つ確かめる。どちらも数秒で終わる。

```bash
python3 tools/narration.py --check   # セリフがシーンに収まるか（実測）
node tools/lint-copy.js              # 入稿できない表記が無いか
```

### ③〜⑤ 書き出し

```bash
tools/pipeline.sh build
```

設定の反映 → フォントのサブセット化 → 表記の点検 → ナレーション合成 → 映像の書き出し
を順に実行する。1分半ほど。

**新しい漢字を足したらフォントの作り直しが要る。** `build` に含まれているので、
個別にコマンドを叩くときだけ `node tools/subset-fonts.js` を忘れないこと。
飛ばすとその字が豆腐（□）になる。

### ⑥ 検品

```bash
tools/pipeline.sh qa
```

表記・レイアウト・文字の大きさ・コントラスト・動画仕様・音量・尺のずれを見る。
**1件でも外れたら終了コードが 0 にならない。通るまで直す。**

落ちたときの読み方は [`references/design.md`](references/design.md) にある。
たいていは②で文言を足した副作用なので、②に戻って直す。

## 守ること

動画に入れてはいけないものがある。`tools/lint-copy.js` が機械的に拾うが、
書く前から意識しておくほうが早い。理由は [`references/compliance.md`](references/compliance.md)。

- **価格・割引・キャンペーン**。価格は変動するので差し替えが必要になり、ガイドライン違反にもなる。
  買い切りを訴求したいなら「支払い回数」という構造の話に置き換える。
- **競合の実名**。「サブスクリプション型」のような一般名詞にとどめる。
- **Amazon への言及・カートへの誘導・URL・連絡先**。
- **根拠のない最上級**。実績を出すなら調査主体・対象・期間を同じ画面に出す。
  注記を消して使い回さない。

そしてもう1つ、ガイドラインではないが効く原則。

- **音を消しても意味が通るように作る。** 商品ページの動画はミュートで自動再生される。
  伝えたいことは画面文字に出し、ナレーションは補助に留める。

## つまずきやすいところ

実際に踏んだものだけを [`references/design.md`](references/design.md) に残してある。
検品が落ちたとき、音がおかしいとき、文字が消えたときは先にそこを見る。

代表的なものを挙げておくと、

- 背景が `position:absolute` だと、位置指定のない本文より**後に**描画される。
  `z-index` を指定しないと、transform を持たないテキストが背景に隠れて消える。
- ffmpeg の `amix` は入力が終わるたびに残りを再正規化するので、
  短いセリフを並べると全体に右肩上がりのゲインがかかる。
- `alimiter` は自動レベル調整が既定でオン。`level=disabled` を付けないと音量が揺れる。

## 設定

配色・尺・声・検品基準・入稿ルールは全部 `project.json` にある。
ツールはここを読むので、書き換える場所を探す必要はない。
矛盾した設定（ナレーションの目標音量が検品基準の外など）は読み込み時に止まる。

色を変えたら `node tools/apply-config.js` で `src/theme.css` に反映する
（`tools/pipeline.sh build` に含まれている）。
